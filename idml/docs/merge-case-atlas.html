3-way merge case atlas — ordered trees & graphs (IDML)

One parent holds 1..n children. Each case is a common ancestor (base) with two independent edits (left, right) and the expected merge. Position is stored as a (predecessor Self, successor Self) pair — relative to concrete siblings, never an ordinal index that shifts when siblings are added or removed. Every rule must behave identically whether a parent holds 3 children or 30.

Extends the base atlas (uc01–uc13) along the multi-sibling axis. The genuinely new categories — ones that cannot be reasoned about from a 2-child intuition — are N2 same-gap multi-insert & intra-branch chains, all of N5 (anchor-fallback cascades), N7-cycle (graph-only), N8 reference/order consistency, and N9 script-overlap granularity. Store each as case-name/{base,left,right}.idml + expected.json with keys ordering_policy, anchor_fallback, conflict_type.
